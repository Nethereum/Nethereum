# CoreChain & Storage — Nethereum 7.0

Nethereum 7.0 ships a complete Ethereum node storage-and-execution subsystem in .NET. Give `Nethereum.CoreChain` a block and it tells you whether that block is valid and what state it produces (naming the exact check that failed when it doesn't); give it transactions and it seals a block; point it at a block source and it follows a chain to the tip, checkpointing and rewinding on its own — the same engine that runs behind the mainnet follower, AppChains and DevChain. Underneath it, `Nethereum.CoreChain.RocksDB` persists everything a chain accumulates on disk behind the same interfaces an in-memory store implements, with a PBSS-style path-keyed state trie, a bounded node-history reverse-diff journal that serves as-of proofs and drives reorg rewind, and a geth-compatible freezer tier for ancient history. That freezer is two new packages of its own — `Nethereum.Freezer`, the dependency-light byte-level append-only ancient store that reads and writes geth's on-disk format, and `Nethereum.CoreChain.Freezer`, where Nethereum's block types meet that format and the EIP-7745 filtermaps log index answers `eth_getLogs` over frozen history. `Nethereum.CoreChain` and `Nethereum.CoreChain.RocksDB` existed at 6.1.0 but were rebuilt across this range (the executor/importer/producer/follower pipeline, path-keyed storage, node history, freezer wiring and filtermaps are in-range work); `Nethereum.Freezer`, `Nethereum.CoreChain.Freezer` and the shared-test-vector project `Nethereum.Chain.TestData` are net-new for 7.0.

## Nethereum.CoreChain — The Node Engine

Run an Ethereum node's brain in .NET, with no database, networking or consensus client of its own — those bind to its interfaces from outside. `BlockExecutor` is the canonical state transition `π(σ,B)`; everything else is a thin layer that drives it.

* Execute a block against some state, persisting nothing — `BlockExecutor.ExecuteAsync(header, txs, uncles, withdrawals, BlockExecutionOptions, ct)` returns a `BlockExecutionResult`; `BlockExecutionRole` (`Building`/`Validating`/`Simulating`) is the difference between sealing a block, judging one, and running it for `eth_simulateV1`-style speculative execution
* Import a block and get a pass/fail verdict with named checks — `BlockImporter.ImportAsync` → `BlockImporterResult` (`RootMatches`, `FailedChecks`, `DescribeRejection()`); a rejection always names itself
* Seventeen self-naming validity checks — `IBlockValidityChecks` / the `BlockValidityCheck` enum, each with a stable wire identifier (`stateRoot`, `receiptsRoot`, `gasCapacity`, `blobFieldFormat`, `blockAccessListHash`, `blockAccessListMalformed`, `requestsHash`, `gasLimitBound`, `withdrawalsRoot`, …); `Identifier()` throws for an enum member with no registered wire name, so adding one without a name fails loudly. `BlobFieldFormat` refuses an imported block whose header's `BlobGasUsed` / `ExcessBlobGas` presence does not match its fork: both are required from Cancun and must be absent before it
* Seal a block from chosen transactions — `BlockProducer.ProduceBlockAsync(transactions, BlockProductionOptions)` orders via `ITransactionOrderingPolicy`, computes roots via `IBlockRootsProvider`, encodes via `IBlockEncodingProvider`, hashes via `IBlockHashProvider`, and persists bodies; production is serialised behind a lock. Headers of a fork that carries blob fields get `BlobGasUsed` (the blob gas of the included transactions) and `ExcessBlobGas` (computed from the parent by the same rule the importer checks); the fork's blob schedule comes from `BlockProducer`'s optional `hardforkConfigFactory` constructor argument, which defaults to the mainnet hardfork registry
* Follow a chain and keep following — `FollowerChainNode.RunAsync` / `FollowerService.RunAsync` in either a legacy forward-stream mode or a tip-event-driven mode, committing the cursor per matched block, checkpointing periodically, consulting an `IValidationPolicy` on divergence, and fast-starting at pivot + 1 on a completed snap sync (`SnapPhase.Complete`)
* Compute a state root without walking the whole state each block — `IncrementalStateRootCalculator` (`IIncrementalStateRootCalculator`) warm-starts from the previous root and applies only dirty accounts and storage slots, handling SELFDESTRUCT wipes, with a full-walk fallback and a compute-then-commit split (`ComputeStateRootWithoutPersistAsync` + `PersistPendingStateAsync` / `DiscardPendingState`); `BinaryIncrementalStateRootCalculator` is the EIP-7864 binary-trie variant, `PatriciaBlockRootCalculator` the block-level (tx/receipt/withdrawal) root calculator
* Serve EIP-1186 proofs at the tip or as-of a retained block — `ProofService` (`IProofService`), with as-of proofs served through `IHistoricalProofCapable.ProofServiceAsOf(...)`, gating on root presence and mapping a gone root to JSON-RPC −32000
* Undo blocks after a reorg — `RewindCoordinator.RewindToAsync(target, RewindPolicy)` (`JournalFirstThenSnapshot` / `JournalOnly` / `SnapshotOnly`) selects flat-state journal replay, node-history recovery, or nearest checkpoint, reporting a `RewindOutcome`
* One storage composition root — `IChainStoreBundle` (blocks, transactions, uncles, withdrawals, block-access-lists, receipts, logs, state, trie nodes, metadata, diffs, checkpoints, `BeginBatch()` cursor-last); `InMemoryChainStoreBundle.Open()` supplies the whole storage side for tests
* A storage seam for building the state trie from flat state — `IFlatStateTrieGenerator` has `GenerateTrieFromFlatAsync(expectedRoot, progress, ct)`, which returns a `FlatTrieGenerationResult` (the generated `Root` plus `AccountsScanned`, `SlotsScanned`, `AccountRootsRewritten`, `DanglingSlotsDeleted`), and `PruneFlatStateBeyond(durableTasks)`; the snap/2 bootstrap in `Nethereum.DevP2P.Sync` uses both, and records the durable `SnapPhase.Generating` phase in `SnapSyncState` while generation runs
* Genesis predeploys mainnet has — `SystemContractPredeploys` holds the runtime code and activation fork of the EIP-4788/2935/7002/7251/8282 system contracts and the EIP-7997 keyless CREATE2 factory, allocating exactly the accounts a given fork has (`AllocateIfAbsentAsync` is a no-op when the account already has code)
* Chain-agnostic seams — fork behaviour gated by an injected `IChainActivations` (`FixedChainActivations` for AppChains/DevChain/tests, schedule-driven `MainnetChainActivations` for mainnet); the consensus-admission seam (`IConsensusBlockGate`, `ConsensusGatedBlockExecutor`, `AlwaysAcceptConsensusBlockGate`) and the trusted-tip seam (`ICanonicalStateRootSource`) are extension points, not baked into execution
* Full `eth_*` / `net_*` / `web3_*` JSON-RPC over all of the above — `RpcHandlerRegistry` + `RpcDispatcher` (`AddStandardHandlers()`), including filters, `eth_simulateV1` multi-block simulation (state/block overrides, precompile move/override, a running nonce and one gas pool across the request; an invalid simulated transaction returns geth's code — `-38010` nonce, `-38012` fee cap below base fee, `-38013` intrinsic gas too low, `-38014` insufficient funds — rather than `-32603`), `debug_traceTransaction` / `debug_traceCall`, and `eth_subscribe` `newHeads`/`logs` over `WebSocketRpcHandler`. Any other subscription type, or a missing one, is refused with `-32000` and geth's message `no "<type>" subscription in eth namespace`; in 6.1.0 such a request returned a subscription id and streamed new block headers
* RPC behaviour aligned with geth and execution-apis — EIP-1898 block-hash parameters on `eth_getBalance` / `eth_getProof` / `eth_getBlockReceipts`; malformed block tags, an `eth_getLogs` `toBlock` beyond the head and an over-long `eth_getStorageAt` key are rejected with `-32602`; `eth_getBlockReceipts` returns `null` for an unknown block; `eth_estimateGas` pads the estimate by `ChainConfig.EstimateGasPaddingPercent` (default 10%); `eth_createAccessList` no longer double-counts intrinsic gas; `eth_feeHistory` reports `baseFeePerBlobGas` and `blobGasUsedRatio`; `eth_call` / `eth_estimateGas` resolve the block's fork on schedule-configured chains; `web3_clientVersion` reports the real package version; `eth_config` (EIP-7910) lists `DEPOSIT_CONTRACT_ADDRESS` in `systemContracts` from Prague, taken from the new `ChainConfig.DepositContractAddress` (default the zero address; set to mainnet's deposit contract by the mainnet node factory; read from a genesis file's `config.depositContractAddress` by `StandardGenesisLoader`), and reports `last` as the furthest scheduled fork after the head, or `null` when none is scheduled
* Engine API handlers for a consensus client or a second node — `EngineApiService` behind `AddEngineHandlers()` serves `engine_newPayloadV3`/`V4`/`V5`, `engine_forkchoiceUpdatedV3`/`V4`, `engine_getPayloadV3`/`V4`/`V6`, `engine_exchangeCapabilities` and `engine_getClientVersionV1`; a payload with an unknown parent reports `SYNCING` and one that fails validation reports `INVALID`. `engine_newPayloadV4` / `V5` return `-32602` for a `null` `executionRequests` list or one whose elements are out of `request_type` order, share a type, or carry no request data, and a payload's gas limit, gas used, timestamp, blob gas used and excess blob gas are read across the full uint64 range, with a value outside it rejected as `-32602`

## Nethereum.CoreChain.RocksDB — Persistent Node Database

The on-disk backend for a Nethereum node: blocks, transactions, receipts, logs, accounts, code and the state trie, behind the same CoreChain interfaces the in-memory store implements, so code written against `IChainStoreBundle` runs unchanged on disk. `RocksDbChainStoreBundle.Open(dataDir, …)` is the composition root — it decides which storage regimes are active from `RocksDbStorageOptions` and hands back every store as a property.

* PBSS-style path-keyed state — `RocksDbPathTrieNodeStore` keys a trie node by its `(Owner, Path)` location instead of by `keccak(rlp(node))`, so an update overwrites in place and the live trie stays a fixed number of keys; it skips embedded (<32-byte) nodes, verifies `keccak(blob)` against the reference hash on every read, and wipes a contract's whole storage subtree with one `DeleteRange(owner)` on SELFDESTRUCT. The legacy content-addressed `RocksDbTrieNodeStore` remains the `TrieNodes` handle; hash mode is byte-identical to prior behaviour
* Bounded node history — `RocksDbNodeReverseDiffStore` records a per-block reverse diff of the path-keyed trie, appending the forward state move to the *same* `WriteBatch` (diff and move land atomically), first-write-wins per `(block, owner, path)`; `FindBlobAsOf` seeks a node's value as of block N on a key-major index, `FindBlockByStateRoot` resolves a root to its block, `PruneBelow` drops history below the retention floor, `MaterializingRewindTo` is the node-level rewind step
* As-of serving — with path-keyed state, node history and the key-major index all on, `bundle.NodeServing` (`ISnapNodeStoreSelector` + `IHistoricalProofCapable`) serves proofs and snap ranges as of a retained block via an `AsOfBlockNodeStore` overlay, gated by a fixed-window floor (requests below it throw `StateNotAvailableException` → −32000)
* Freezer history tier — `UseFreezerHistory` moves immutable history out of the LSM tree into `Nethereum.Freezer`'s append-only files; `FreezerReadRouter` is the single routing decision (a block lives in exactly one tier), applied by six thin `FreezerAware*Store` wrappers, with `ReceiptFieldDeriver` re-deriving sender / effective-gas-price on read (the `signer` is required when the freezer is on)
* Filtermaps log index build — `FreezerBackgroundIndexer` is the single writer of the by-hash and EIP-7745 filtermaps CFs, in inline mode (index as blocks freeze) or a pausable background trailer (`BackgroundFreezeIndexing`, `StartBackgroundFreezeIndexing()`); both write through the bulk-SST engine `BulkIndexIngestor` (sorted SST ingest, never a memtable `WriteBatch`), and `FreezerFilterMapsLogStore` + `FilterMapsQueryEngine` answer `eth_getLogs` with `FreezerAwareBloomScan` covering the un-indexed hot tail
* Hot window vs history — the `SplitHistoryStore` option opens two physical databases (a `core/` and a `history/` manager, the latter a `RocksDbHistoryStore`) so bulk history writes cannot stall the hot core; `PromotionEnabled` keeps one database and defers the move via `RocksDbPromotionService.PromoteDurableBlocks`; the `Composite*Store` family unifies reads (hot first, then history). Illegal option combinations are refused outright at `FromManager` time
* Reorg rewind on the bundle — `RocksDbChainStoreBundle` implements `INodeHistoryRecoverable`, so CoreChain's `RewindCoordinator` rolls the trie, flat state and cursor back through node history, falls back to reconciling from the trie on a journal hole, and recommends the nearest checkpoint when neither path covers the target; the archive stores are truncated above the new head
* Boot recovery and durability — `BootRecoveryGate` (clean-shutdown marker, pending-restore honouring, bounded escalation on a torn head), native hard-linked checkpoints (`RocksDbCheckpointManager`), batched persistence (cursor never ahead of data), bulk-SST from-genesis ingest (`SyncBulkSaveService`), and `RocksDbWritePressureMonitor` backpressure. EIP-7864 binary-trie stores (`RocksDbBinaryTrieNodeStore`) are also present
* Write-pressure valves that match each column family's compaction style — `RocksDbWritePressureMonitor` applies its level-0 file-count pause/resume thresholds only to leveled column families; the universal-compaction trie column families (identified from `LiveColumnFamilies`) are left to RocksDB's own signals — a non-zero `rocksdb.actual-delayed-write-rate`, `rocksdb.is-write-stopped` and the immutable-memtable valve — so an ordinary universal merge does not pause state writes
* Native option objects kept alive for the whole native call — the RocksDbSharp `IngestExternalFileOptions` and `WriteOptions` passed to RocksDB (SST ingest in `SnapFlatSstSink`, `BulkIndexIngestor` and `RocksDbFilterMapsStore`, WAL-off writes in `BufferedTrieStorage`, fsync writes in the bundle batch) are `static readonly` instances, and `HistoryBloomScanLogStore` holds its snapshot-bound `ReadOptions` with `GC.KeepAlive`, so the garbage collector cannot finalize a native options object while RocksDB is still using it
* State trie generated from flat state — `RocksDbChainStoreBundle` implements `IFlatStateTrieGenerator`. `GenerateTrieFromFlatAsync` first wipes the account and storage trie column families on a path-keyed store, so a rerun after a failure starts clean; walks the flat accounts and storage in 16 parallel shards by first nibble; builds each account's storage trie from its flat slots, rewrites a flat account whose recorded storage root differs from the generated one, and deletes storage rows that no account owns; and throws naming both roots and the counters when the generated root is not the expected one. `PruneFlatStateBeyond` deletes, in one write batch of range deletes, the flat accounts and storage each durable snap task has not yet covered. The storage of owners that are complete or in progress inside that range is kept, except the not-yet-downloaded range of each in-progress large-contract subtask, which is deleted too
* Flat reconcile and verify report progress on a one-minute cadence per shard — `FlatStateReconciler` emits its per-shard progress line when 60 seconds have passed since that shard's last line, as well as after 1,000,000 accounts or 10,000,000 slots, so a shard walking one very large contract's storage keeps logging; the constructor takes an optional `TimeProvider` for the clock

## Nethereum.Freezer — Geth-Compatible Ancient Store

New package: a dependency-light (no RocksDB, no CoreChain) append-only ancient store for write-once, sequential-by-block historical data — headers, block hashes, bodies, receipts and EIP-7928 block access lists. It reads and writes go-ethereum's on-disk freezer format, so a geth `ancient/` directory imports directly.

* The archive is one lockstep unit — five tables (`headers`, `hashes`, `bodies`, `receipts`, `bals`) that every finalized block writes exactly one item to, from genesis; reads are by absolute block number, `Freezer.ReadCluster(n)` returns all five (with narrow single-table accessors for a subset)
* Geth's on-disk layout — snappy-compressed `.cdat`/`.cidx` rolling data/index files (raw `.rdat`/`.ridx` for the uncompressed `hashes` table), 6-byte big-endian index entries (`FreezerIndexEntry`), and a 3-field `.meta` RLP (version, `virtualTail`, `flushOffset`) that is the commit point
* Write path — `BeginBatch()` → `AppendCluster` (enforces lockstep across all five tables or throws `FreezerConsistencyException`) → `Commit()` (fsync every index, then every data file, then persist every `.meta`); `Reset()` truncates staged-but-uncommitted appends; `Freezer.Encode` runs the snappy codec off the append thread
* Deep-reorg truncation — `TruncateHead(newItemCount)` rejects (`FreezerImmutableException`) any target below the highest `VirtualTail` and is a no-op above the head
* Concurrent-read boundaries — `SealedHead(...)` and `CommittedHead(...)` take the specific table names a reader reads and return the min, so an unrelated slow-rolling table cannot starve the boundary
* Geth import inspection — `GethFreezerImporter.InspectSource` opens a copied `ancient/` directory read-only and returns an `ImportReadiness` (`IsCompleteHistory`, `PrunedGroups`) reporting whether geth's history-expiry pruned any tail-group
* Codecs and primitives — `IItemCodec<T>`, `IdentityByteCodec`, `SnappyItemCodec<T>`, and the lower-level `FreezerTable<T>` / `FreezerIndex` / `RollingDataFiles` / `FreezerTableMeta`
* The pure filtermaps core — the storage-agnostic hashing, byte layout and matcher of geth's EIP-7745-style log index (`Nethereum.Freezer.FilterMaps`: `FilterMapsParams`, `LogValueHasher`, `FilterMapsSchema`, `FilterMapsRowCodec`, `FilterMapsMatcher`, `IFilterMapsStore`) — the format and query logic only; the rendered rows live in RocksDB in production

## Nethereum.CoreChain.Freezer — Freezer Integration & Log Index

New package: the CoreChain layer over `Nethereum.Freezer`, where Nethereum's block types meet the freezer format and a running node uses the freezer as its finalized-history tier.

* Domain codecs — `FreezerCodecSet` bundles the five typed per-stream codecs (`HeaderItemCodec`, `BodyClusterItemCodec`, `ReceiptsItemCodec`, `HashesItemCodec`, `BalItemCodec`); `BlockBodyCluster` preserves the pre-Shanghai `null` vs post-Shanghai empty-but-present withdrawals distinction
* Receipt-field reconstruction — geth trims a receipt to three fields (`ReceiptForStorage`) before freezing; `ReceiptFieldDeriver.Derive` rebuilds `gasUsed`, `logs`, `bloom`, `txHash`, effective gas price, contract address and blob fields (geth's `Receipt.DeriveFields`), so a trie root built from the reconstructed receipts matches the header's `ReceiptsRoot`; the blob base-fee fraction is a fork-aware seam (`IBlobBaseFeeFractionResolver`, default `CancunBlobBaseFeeFractionResolver`)
* The finality-gated write path — `FreezerPromotionService.PromoteFinalizedBlocks` appends finalized hot-window blocks to the freezer in lockstep, commits them as one durability unit, then indexes what is now durably frozen; a block is promoted only once it can never be reorged out. It reads through `IHotBlockWindowSource` / `IFinalitySource` / `IHotBlockWindowEvict` seams (mainnet and AppChain each supply their own) and populates an `IRandomKeyIndexStore` by-hash index
* The read-tier adapter — `FreezerHistoryStore` presents the append-only freezer through six CoreChain node-store interfaces (`IBlockStore`, `ITransactionStore`, `IReceiptStore`, `IBlockAccessListStore`, `IUncleStore`, `IWithdrawalStore`) so a composite store reads frozen history like any other tier; it is read-only (every `SaveAsync` throws; a mutation below the freeze boundary throws `FreezerImmutableException`) and composes a bounded decode-once LRU (`DecodedClusterCache`) so concurrent readers of one block share a single decode + sender recovery
* EIP-7745 filtermaps rendering and query — `FilterMapsIndexer` renders finalized, promoted-but-unindexed blocks one whole epoch at a time (writing nothing until an epoch is fully computed, so a crash re-renders idempotently) and un-renders on a finality regression; `FilterMapsQueryEngine` is the `eth_getLogs` façade that snapshots the indexed-head boundary once, serves `[fromBlock, indexedHead]` from the index and `(indexedHead, toBlock]` from a hot/scan path, and merges the two with no gap and no double-count. `FilterMapsLogResolver` drops index false positives; `IChainView` / `IFinalitySource` (`FreezerChainView`, `FreezerHeadFinalitySource`) are the freezer-backed views the stack runs against, with `LogValueSequence` and `FilterMapRenderer` as the reusable rendering primitives

## Nethereum.Chain.TestData — Shared Sync Test Vectors

New source-only project (no README, no NuGet headline) that holds the shared chain fixtures, workload contracts and sync vectors (`ChainGenesisData`, `ChainRoster`, `WorkloadContracts`, `SyncVectorCatalog`, `SyncVectorManifest`, `ChainStateComparison`) the CoreChain, Freezer, DevP2P.Sync and Sync.Workload test suites drive against. Test infrastructure, not a shipped capability.
